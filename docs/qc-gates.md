# 质检闸门与状态

原则（参考 whitebox-world-studio 交付包）：**如实记录，不代填**。程序只判定能自动判定的；没做的检查写 `not_run`，
人工项只由看过的人标记。

## 闸门

### 渲染前动态闸门（全部路线）

`src/wbs/qc/dynamic.py`，按 `configs/default.yaml` 的 `qc.dynamic_gate`，沿成片时间以 48Hz 采样：

| 检查 | 阈值 |
|---|---|
| 相机 ↔ 碰撞体块最小净距 | ≥ 0.3 m |
| 相机 ↔ 主体（竖直圆柱）距离；主观视角镜头的载体本人豁免 | ≥ 0.3 m |
| 主体 ↔ 体块水平穿插（站在顶面算支撑） | ≤ 0.05 m |
| 主体两两净距（竖向重叠时） | ≥ 0.05 m |
| 主体运动上限（按种类，`qc.dynamic_gate.kinds`）：速度、加速、制动、转弯横向加速度、转向角速度 | 不超；车辆 45 m/s、7、11、10 m/s²、120°/s，人物 12 m/s、8、9、8 m/s²、720°/s |
| 同镜内相机每帧位移 | ≤ 3 m |

运动上限在**源秒**上量：速度逐采样检查；加速、制动、横向、转向先做 0.1 秒平滑，超限持续 0.1 秒以上才计入，低于 1 m/s 时不算横向与转向。
正向路线超限判不通过（`actor_speed`、`actor_accel`、`actor_brake`、`actor_lateral`、`actor_yaw_rate`）；反推路线的轨迹来自真实素材的测量，
加速、制动、横向、转向超限只记 `warnings`。故事路线的 `routes` 由路线编译器按同一组上限生成，手写 `paths` 不自动改写。

同时做**构图预检**（遮挡感知）：按针孔模型把镜头主体（相机注视的人物，未指定时为第一个人物）的外接圆柱投影到每个非主观镜头的画面，
并对碰撞体块做射线遮挡采样（包围盒 slab 检测）；
采样点在画内且至少 34% 未被挡住的帧才算可见，可见帧需 ≥ 90%（`qc.framing`）。报告另记每镜被挡帧数、主体尺寸中位、实测景别与角度。
长镜头路线同样做这项预检。

### 镜头语法与可读性（渲染前与 `wbs qc`，默认只警告）

`src/wbs/qc/grammar.py`，写 `reports/镜头语法与可读性.json`，进入 `质检汇总.json` 的 `checks.grammar_readability`，不计入 technical；
`qc.grammar.enforce` / `qc.readability.enforce` 设为 true 时改为判不通过。

| 检查 | 规则 |
|---|---|
| 声明与实测 | 景别按主体未裁切尺寸（人物类用身高占画高，车辆等用最大边占画幅），角度按相机俯仰、滚转 ≥ 5° 为斜角；与分镜声明不符时警告 |
| 建立镜头 | 多镜片首镜为远景或大远景 |
| 景别多样 | 至少两档；近景与特写合计 ≤ 50% |
| 30° 规则 | 相邻两镜注视同一主体、实测景别相同、距离比在 2/3–1.5 之间时，机位方向变化需 ≥ 30° |
| 180° 轴线 | 以主体运动方向为轴（静止时取两主体连线）；相邻两镜分在两侧、且都偏离轴线 20° 以上、镜内没有跨轴时警告 |
| 屏幕方向 | 主体运动在相机右方向上的分量，切点前后都 ≥ sin 20° 且符号相反时警告 |
| 节奏 | 每 10 秒镜头数与单镜中位时长，对比同类参考导演卡的范围 |
| 铺垫可读性 | 每个 setup 事件所在镜头里，`targets` / `focus_region` 在某一帧占画幅宽度 ≥ 5% 且 ≥ 50% 未被挡（`qc.readability`）；没写目标时警告 |

结构树批量两项任一不过就自动换种子（≤5 次），结果与每次尝试写 `reports/制作数据检查.json`；渲染后再按同一规则复查一次。
实测 300 个随机样本：296 个首次通过，其余在 4 次以内全部通过。

### 反推静态闸门（[D2] 阶段 2）

`src/wbs/qc/static.py`，用最终相机渲染每镜首/中/尾帧，与原片同位置帧比较：

| 检查 | 阈值 / 方法 |
|---|---|
| ① 布局一致 | 边缘密度格 / 亮度格相关系数取大 ≥ 0.35（粗指标，需看三图证据） |
| ② 结构线倾角 | 原片前 3 条主导线与白模最近线的倾角差 ≤ 15° |
| ③ 镜像 | 原片水平光流符号 vs 白模相机航向变化符号；主体横移方向符号 |
| ④ 主体占幅 | 占幅面积差 ≤ 10% |
| ⑤ 体块互嵌 | 碰撞体块两两重叠深度 > 0.3 m 即失败 |

证据：`reports/static_gate/<镜>_<first|mid|last>.jpg`（原片｜白模｜白模镜像）。修正循环记录：`reports/反推修正记录.json`。

## 渲染后检查（`wbs qc`）

| 报告 | 内容 | 判定 |
|---|---|---|
| `media-check.json` | 全片解码错误、帧数、帧率、分辨率、音轨、sha256 | 与 scene.json 完全一致、无音轨、零解码错误 |
| `剪辑检查.json` | 镜长统计；Blender 逐帧实际激活相机的切换帧 vs 计划切点（`basis: blender_active_camera`）；画面切点检测作辅助证据 | 切换帧与计划完全一致、每帧用的都是本镜相机；画面检测的漏报/多报只作警告 |
| `景别对照.json` | 第一个人物最远/最近投影高度与比值；逐镜主体（相机注视的人物）可见率（Blender 审计逐帧 `scene.ray_cast` 得到的 `occluded_fraction`）、被挡帧数、尺寸中位 | 每个非主观镜头主体可见 ≥ 90%（被挡超过 66% 的帧不算可见） |
| `速度测量.json` | 源秒/成片秒两个时基的峰值、平均速度与路程；`motion_peaks_source` 为闸门量得的各项峰值与上限 | 描述性 |
| `朝向检查.json` | 96Hz 朝向采样，最大偏航速率；车辆另测车头与行驶方向的偏差 | 不超该种类的 `yaw_rate`；车头偏差 ≤ 30° |
| `镜头语法与可读性.json` | 见上节 | 默认只警告 |
| `构建一致性.json` | Blender 实测主体/相机 vs scene.json 计算 | 主体 ≤ 1 cm，相机 ≤ 1 cm + 抖动幅度 |
| `diversity-review.json` | 故事/摄影/制作结构三类指纹；与工作区其他任务的精确与相似匹配 | 描述性；“无匹配不代表原创” |
| `时序证据.json` | 黑帧、单帧闪帧/掉帧、计划切点之外的亮度闪烁（p95）、非计划切点、冻结段；VBench 已安装时附模型分数 | 写入体验报告 `temporal_stability`，作为自动证据；**不并入 technical**，正常速度观感仍需人工 |
| `导演卡对照.json` | 本片导演卡与参考样例（叙事/运动分开）的镜头数、镜长分布、事件数、剧本长度、字段完整度 | 只作参考，不评价故事好坏 |
| `experience-report.json` | 逐项 status + observed + evidence_paths | 见下 |
| `质检汇总.json` | 四类状态与各检查结论 | — |

故事驱动任务还有 `故事评审.json`：分层规划每层的尝试次数与契约问题、评审-修正历史（mock 下为 skipped）、机械检查
（镜长 1.3–5 秒、事件 4–9 个、转折位于全片 20%–85%、铺垫早于转折至少 1 秒、每镜有动作、有路线交接与“仅在剧本”说明），
以及把规划转成场景后的渲染前检查结果（运动上限、穿模、遮挡、镜头语言、语法与节奏、铺垫可读性），供真实模型的评审-修正回路逐条处理。

## 反推真值评测（`scripts/reverse_benchmark.py`）

用平台自己渲染、真值已知的视频（5 条强制运镜组合的多镜头片 + 1 条 6 镜故事片，共 26 镜、20 个切点）比较各后端。
白模是简单的合成域，结论只用于在同一输入上排序，不代表真实素材。2026-09-27 本机结果：

| 项目 | 原有实现 | 新后端 | 结论 |
|---|---|---|---|
| 切镜 F1（±1 帧） | builtin 1.00 | PySceneDetect 0.82、TransNetV2 0.67（相邻灰色镜头相似时漏切） | 默认保持 builtin |
| 主体占幅 IoU / 面积误差 / 检出率 | motion 0.20 / 0.129 / 89% | Grounding DINO + SAM 2.1：0.64 / 0.066 / 100%（GPU，每条 30–50 秒） | 有 GPU 工作环境时建议开启；默认仍 motion |
| 相机轨迹 ATE（Sim3）/ 相对旋转误差 | heuristic 2.74 m / 13.0° | DA3：2.39 m / 9.7° | 总体提升不到 30%，默认仍 heuristic；按运镜差异很大（下表） |

| 运镜 | heuristic ATE / 旋转误差 | DA3 ATE / 旋转误差 |
|---|---|---|
| 推 | 3.10 m / 10.6° | 1.16 m / 2.9° |
| 拉 | 2.40 m / 9.2° | 0.95 m / 3.2° |
| 手持 | 2.27 m / 9.0° | 1.25 m / 2.5° |
| 摇（相机不移动，只比旋转） | — / 28.5° | — / 14.6° |
| 横移 | 4.11 m / 8.6° | 3.59 m / 9.2° |
| 跟随 | 1.25 m / 2.1° | 3.21 m / 1.6° |
| 6 镜故事片（混合） | 2.36 m / 13.1° | 2.49 m / 18.2° |

DA3 在跟随和快速横移镜头上常把相机估成几乎不动（恢复的路径只有真值的 1%–14%）：相机随主体移动、地面大面积无纹理时视差很少。
位姿估计失败的镜头也可能让相机跳变，动态闸门会如实报 `camera_jump`；几何求解对每镜记录最快相机速度，超过 25 m/s 的镜头在
`job.json` 的 `solver.geometry.shots[].suspect` 里标出，便于对照启发式结果或人工修正。
另外试过“把主体遮掉再算 DA3 位姿”，两条样片误差都变大（白模里主体本身就是主要纹理），未采用。米制尺度（DA3METRIC-LARGE）
在白模上把机高估成约 0.6–0.8 m（真值 1.6 m），因此几何求解的尺度默认用假定机高。完整报告：`workspace/reports/reverse_benchmark_*.md`。

## 四类状态（生产与复核记录）

| 字段 | 谁来定 | 取值 |
|---|---|---|
| `technical` | 程序：媒体、动态闸门、剪辑、朝向、构建一致性、景别可见率合并 | passed / failed / not_run |
| `sampled_visual` | 人：看过故事板、关键帧、切点前后帧 | passed / failed / not_run（默认） |
| `normal_speed_viewing` | 人：以正常速度完整看过 | passed / failed / not_run（默认） |
| `curation` | 用户：是否采用 | adopted / rejected / pending（默认） |

标记：`wbs review mark <任务目录> --field ... --value ... --reviewer 姓名 --note ...`，写入台账并同步到报告。

## V2V 检查边界（Skill v3）

只做机械检查：JSON 契约、文件存在、可解码、编号唯一、依赖齐全。不做视觉评分、不自动改提示词或重生成；
`package_ready` 只表示可提交的文件齐全。mock 图片永远不会让 `package_ready` 为 true。
