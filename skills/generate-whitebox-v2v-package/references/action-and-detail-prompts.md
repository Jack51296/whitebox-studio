# 视频打斗写法与图片真实感、细节优化

在现有 SP 规则上补充两个明确的优化方向：**视频提高动作表达的清楚程度，图片提高真实感与视觉细节。** 写打斗、躲避、负重、碰撞等视频动作时读第1—3节；写生图提示词时读第4—5节。图片优化应让场景、建筑和道具像真实地点和实物的摄影照片，不以增加人物姿势、动作图或连招为目标。第6节为资料依据。它不增加剧本审核、完整看片、生成后验图或自动修图节点。

## 1. 先确定是哪一种输出

| 输出 | 要写什么 | 沿用什么 |
|---|---|---|
| 逐镜视频 | 在镜内时间中发生的动作、攻防因果、受力与收势 | 白模摄影、主体整体路线、时刻、镜长、切点；剧情的行动和结果 |
| 静态参考图 | 真实结构与比例、材料差异、加工与使用细节、可信光照及摄影层次 | 必要空间关系与本图状态；以场景和非人物资产为主 |

踢击、后仰躲避等武打细节写进视频提示词；生图提示词重点是实景和实物的真实感。不能因剧本出现踢击，就增加人物动作图。确需人物出现在参考图时，只允许实际远景场景里的小比例人物；不增加中近景、肖像或独立全身姿势图。

## 2. 把动作写成可见的因果链

先读两文本和总览中已有事件，再展开以下与本镜有关的部分；不要机械把全部项目塞进每一镜：

**稳定角色标签 → 起势及支撑 → 发力部位与路径 → 对方反应 → 接触或擦过 → 收势及切出状态。**

- **归属明确。** 每次攻防转换重新写出动作主语。用“深灰夹克者”“浅色连帽衫者”等稳定标签，不用人名，不只用会因交叉而改变的“左边的人”。
- **动作具体。** 将“激烈打斗”“快速攻击”写成源剧情需要的踢、打、挡、闪；选清一种攻击路径和目标高度。直踹、横向扫踢、回旋踢不可当同义词混写。
- **支撑可信。** 关键踢击说明承重脚与出腿侧；侧闪、后仰说明重心、膝部与躯干如何配合。避免只转头躲开整个身体范围的攻击，或双脚没有支撑仍保持普通站姿。
- **反应对应。** 后仰是承重转换、膝部缓冲和躯干倾斜共同形成，头肩随躯干退出攻击线；颈部自然衔接。动作幅度服从原站位、通行空间和时间，不借此新增一段后撤、滑行、翻滚或腾空。
- **结果唯一。** 原剧情未命中就写可见间隙、攻击经过与保持平衡；已有命中则写接触部位、受力方向与相应反应。不要同一击既“擦过无接触”又“重重撞飞”。反应发生在攻击接近或接触后，不能无原因先倒地。
- **接续完整。** 写必要的收腿、落脚、回正、恢复持握和切出姿态，使下一镜接得上；不因切镜重复起手或把道具换手。持箱的手不能同时格挡，原剧情没有放箱就不能为了好写武打先放下。

白模若只有棋子平移，把剧情中的完整动作补成真实肢体表演；不要复制棋子姿态。若剧情只写“短暂交手”，可在该事件窗口内具体化少量合理攻防；不得新增武器、改变命中结果、转折、整体路线或镜长。左右肢体未指定时可选择与持物和接续相容的方案，并全程保持一致，不伪称该细节来自源片。

## 3. 镜内时序、速度与示例

按已有起势、接近、接触／擦过、收势窗口编排；没有细分秒数时使用事件顺序，不编造小数时间。短窗口保留关键攻防和必要回收，减少装饰动作。不要用新增切镜、慢镜头或延长时长来容纳额外连招。

快速出招可写“短促蹬地、迅速转髋、腿沿明确轨迹掠过、立刻收回”；受力可写衣料跟随身体拉扯、鞋底与地面摩擦、既有可移动物对接触作出反应。只写与现场相符的反馈：干净地面不强加烟尘，未接触不出现撞击反弹。保留原片承重、观察和决定的停顿，不全片统一加速。

不要用摄影特效代替动作清楚：不追加镜头震动、环绕、推近、慢动作或夸张拖影。原镜若看不见脚，只写可见的躯干反应和必要受力，不要求摄影补拍脚部。节制使用解剖细节，不在远景堆指节与微表情。

### 视频示例：踢击—后仰避让—收势

仅用于原事件确有此攻防、并有相容支撑与时间的镜头。以下是“动作”段的写法示例，不能复制成所有影片的新增连招；最终仍附上本片实际镜号、时间、参考图与摄影。

> 深灰夹克者在既定进攻位置以左脚承重，迅速转髋抬起右膝，右腿展开，沿横向弧线扫向浅色连帽衫者原先的肩颈高度。浅色连帽衫者在原站位范围内将承重转向后侧脚，双膝轻屈，躯干整体后倾，头肩随身体退出攻击线，颈部自然延续躯干方向。来脚从面前迅速掠过，脚与身体之间留有可见间隙，未发生接触。深灰夹克者随即屈膝收腿，落回既定步点；浅色连帽衫者在来脚通过后回正躯干，双方接入原镜末态。进攻、避让和回收均落在源镜既有事件窗口内，整体行进路线和摄影沿用白模。

这段把“踢一下，对方躲开”变成可执行的动作。若源剧情是正面直踹、腹部攻击、格挡命中或手持重物，应按本次情境重写，不照抄腿侧、目标和反应。

## 4. 生图优化目标：真实感与视觉细节

目标是让图像像在真实现场拍到的场景与物体。保留既定空间关系后，重新设计可信的真实造型，补上材质、连接、表面和光照的可见依据；不能只给白模贴纹理，或只追加“照片级、电影级、8K”。每条完整 prompt 按画面需要选择以下层次，不逐项堆满无关细节：

1. **用途与画面重点**：全景说明整体环境与区域连接，局部图说明转折所需结构，资产图说明形态与识别特征。按地点和时段明确无人或有合理远景小比例背景人物，不默认清空开放街道。
2. **结构与尺度可信**：明确建筑体量、前后高差、开口、板材厚度和承重关系，让窗、门、护栏、提手等具有与用途相容的比例。白模只是空间依据；真实外轮廓、边缘收口和构件层次需要重新设计，不能保留玩具般的夸大倒角或单一方块造型。
3. **构造与连接具体**：选与对象有关的框架、角件、接缝、铰链、螺栓、压条、法兰、提手等，说明它们如何组成可使用的物体。构件应有安装位置和厚度，与支撑或地面接触自然；不要只在表面随机撒螺丝或刻线来冒充细节。
4. **材质有区别**：分别写适用物体的表面特征和受光方式，例如涂漆钢板的大面较柔和、露出金属的边缘出现窄高光；玻璃反射周围环境并在适当条件下有通透层次；木材有顺纹变化，混凝土有克制的颗粒和细小孔隙。不要所有表面都同样光滑、同样反光或像塑料。
5. **细节有位置和成因**：加工接缝、密封边、局部色差、经常接触处的轻微磨亮、室外接缝附近的水痕等，按环境和物体新旧程度选择。划痕、锈迹、灰尘、潮湿都不是必选项；洁净的新建筑也能通过施工细节和材料差异表现真实。避免重复贴图感、等间距污渍和均匀做旧。
6. **光照、反射与接触一致**：写光源方向、软硬、环境补光及合理冷暖关系；相邻物体的投影方向相容，箱底、墙脚或连接处有自然接触阴影。反射应对应周围环境，干湿区域区别有依据。同一场景跨图保持世界中的光源位置、天气和光色；观察角度变化后亮面、阴影和反射随之改变，不机械要求每张图都从画面左侧来光。不为真实感统一加雨水、雾、逆光或镜头光晕。
7. **摄影层次自然**：交代观察角度、前中后层次和主要焦点，让尺度与纵深可信；全景保留空间可读性，局部突出关键结构而不过度虚化。高光和暗部保留适量层次，颜色克制，边缘清晰但不过度锐化，不用浓重滤镜、夸张HDR或满屏颗粒代替实拍质感。曝光服从故事光线，不要求所有区域同样明亮，也不同时要求浅景深和全域锐利。不必臆造焦距和相机参数。
8. **细节服从景别**：全景优先楼体形态、材料分区、区域高差、反射与远近层次，局部再写板缝、连接件和可见磨损。细节服务主体，不强迫全景读出每颗螺丝，不为增加细节搬入其他区域设施。
9. **当图限制**：保留功能关系、不迁入其他区域背景、不新增剧情设施；人物图范围、白模残留、文字标注与拼图等限制写入同一 prompt。

减少“超真实、电影级、8K、细节拉满”的重复。把“精细金属门”写成“折边喷漆钢板门嵌入厚门框，铰链轴附近积灰，常握门把手表面被磨亮，侧光在露出的金属边缘形成窄高光”。这是有对象、有位置、有材料响应的正面设计。

美术补充不得改变动作条件：可以细化已有箱体的框架和板缝，不能在必经空隙加斜撑；可以设计既有栏杆的材质，不能在翻出缺口处补栏杆；可以细化已有窗户，不为好看的光线新增剧情出口。

还应主动补符合场景的生活或自然内容，而不只给已有物体加纹理：城市街道的路人和设施、树林的植被层次和地表变化，按 [gpt-image-environment.md](gpt-image-environment.md) 编写。合理背景路人不属于新增剧情角色，仍只以远景小比例出现。

图生图首先说明白模帧只提供哪些必要关系，再完整写出真实设计。外观依赖图仅继承明确的材料、造型或光色，并排除布局、背景、状态和摄影；不写“完全还原输入图”。全景默认纯文生图，实际图片输入为零。完整示例见 [image-prompt-examples.md](image-prompt-examples.md)。

## 5. 写法示例：从抽象真实到可见真实

较空泛的写法：

> 真实的集装箱场景，电影感，材质精细，光影自然，细节丰富。

可替换到完整提示词中的真实感描述：

> 将该区域设计成实地摄影般的货运集装箱场景。集装箱由厚实边梁、角柱和有连续起伏的瓦楞钢板组成，板缝与框架收口清楚，箱体稳妥落在混凝土地面。灰绿漆面的大部分区域完整，迎光面略有自然色差，易碰边角局部露出偏冷金属；不同材质的反光有区别，不呈统一塑料光泽。日光从侧上方照入，瓦楞凹凸产生连续明暗，巷内阴影仍保留细节，箱底有自然接触阴影。地面只有沿边缘积聚的少量尘土，整体保持与场地用途相符的状态。前后箱排有清楚纵深，真实尺度、正常曝光和克制色彩共同形成现场拍摄质感。

这段细化的是结构、材质与光照，不新增人物、动作、通道或剧情设施。最终仍应嵌入本图用途、必要空间关系、输入图片的角色与针对性限制，形成可独立发送的完整 prompt；不能让示例取代当前场景设定。

真实感优化在提交前写入每条 prompt，由 `prompt_constraints` 承载针对性限制；不添加生成后验图或自动修图。偶有远景人物时，遵守既有人物限制与 `state_scope`，不另开姿势图生产步骤。
