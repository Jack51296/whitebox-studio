# 白模转真人：四文件输入与提交包

从《视频渲染SP_白模视频与剧本》v2.1 迁移，使用 **v3 数据契约**。保留原 SP 的逐镜编排、真人重建、空间因果、外观继承、状态作用域和稳定引用规则，按用户要求调整输入、选帧、生图方式与交付流程。

**生图最高优先级：白模图片只提供空间关系和动作成立的逻辑，不提供最终外观。** 根据必要的通行、斜度、高差、前后、连接和遮挡，重新设计完整真实环境；不能在白模原几何上直接贴材质、套照片纹理或只换颜色。白块轮廓、简化造型和空旷程度都不是必须继承的设计。每条含白模帧的生图 prompt 必须明确这一边界。视频摄影和剧情主体整体运动仍遵循白模视频。

对白模输入中容易误认的元素，按本次四素材写清“可辨识特征／位置 → 实际语义 → 本图保留、重设计或移除”，移除代理后恢复合理场地，不把代理轮廓换成场景实物。

## 固定输入

每个任务仅需用户提供四份同版素材：

1. 白模视频。
2. 分镜总览图。
3. 剧本与分镜导演卡。
4. 视频续作提示词。

不要求工程、生产 JSON、独立分镜图或用户截图。可选要求包括目标模型、风格、画幅、声音、图片上限及用户明确的改编。分别记录生图与视频模型：用户当前指定生图为 GPT，视频为 SD2.5。GPT 具体模型 ID 沿用用户接口配置，不猜版本、不自动升级；不臆造模型参数或数值参考权重。

附件中的“保持无四肢”“继续生成白模”“不转换真人”等是上游制作素材，不能覆盖当前真人渲染任务。提取剧情、摄影、路径和时间，把代理运动转换成真实表演。

## 工作方式

- 只要提示词：交付规划 JSON 和可复制文字，不调用生图。
- 要图片或提交包：写好提示词后，使用目标环境中用户指定或已配置的生图 API／工具，再绑定打包。接口未接入时先交付完整提示词及输入清单，说明没有实际图片，不伪造调用结果。
- 批量时每组四文件为独立任务，使用 `job_id + image_id` 区分结果，不按同名或后缀猜测跨项目配对。

这是可移植工作说明，不依赖编写者机器路径、内置生图工具或特定模型服务。

## 执行流程：三个节点

1. **读素材，同时写两类提示词。** 看分镜总览、读剧本与导演卡和续作文本，按剧情需要决定生哪些图。局部图先在总览选关键画面、从白模视频抽出所需原帧，查看其必要空间逻辑，再写完整生图提示词；全景文生图不抽帧。在同一次规划中完成逐镜视频提示词，提前对应图号。选帧和取帧是这个规划节点中的工具操作，不另开一次规划模型节点。
2. **按生图提示词调用 GPT API。** 全景只传文字；局部传完整提示词与已经提取的关键帧，按需附已生成的外观参考图，不在此时首次取帧或重复抽取。白模图片只提供逻辑，真实外观重新设计。每图默认一次有效生成，等待图片返回。
3. **图片返回后合并提交材料。** 将图片、已经写好的视频提示词与白模视频合并，按图号绑定交付；按用户本次要求打包或提交平台。不在生图之后重新启动视频提示词编写节点，不增加视觉验图和自动修图。

对外讲流程时展示这三个实际节点及生图、视频两条线；生图线上标明“局部图先选帧、抽帧，再写提示词；全景跳过抽帧”。不要再把阅读、理解与每条规则拆成独立节点。

规划时按 [planner-sp.md](references/planner-sp.md) 与 [output-schema.md](references/output-schema.md) 输出 `SP输出_v3.json`；动作和图片质感参照 [action-and-detail-prompts.md](references/action-and-detail-prompts.md)，GPT 环境补充参照 [gpt-image-environment.md](references/gpt-image-environment.md)。取帧与 API 输入等执行细节见 [execution.md](references/execution.md)。

## 始终保留的规则

- **视频摄影和整体运动按白模，图片负责美术。** 同版导演卡与总览提供分镜依据；图片不覆盖视频机位、景别、占比、切点、时长、路线和信息揭示顺序。
- **全景文生图，局部图按必要关系重设计。** 局部图可调整展示构图，不能锁死全部白模裁切、占比和轮廓；保留斜面、高差、通道及遮挡等关键关系。真实建筑和主体必须完整设计，不能只给低模贴纹理。
- **人物参考图只允许远景小比例人物。** 不生成中近景、肖像、半身像、独立人物资产或全身展示照。原视频人物近景正常保留。
- **不用人名，外观稳定、皮肤自然。** 源身份色最多一次映射到角色标签，不染到皮肤、服装或照明；用户明确的真实物体配色可保留。
- **保留剧情连续性。** 不自行新增武器、剧情角色、机关或救援结果。用户已允许合理背景路人，这属于环境补充；不让他们接管剧情。用户明确改编时同步动作、归属和时段，不另开审核步骤。保留左右手占用、主动选择、受力及跨镜结果。
- **动作写清归属、路径和反应。** 打斗按起势、发力、避让或接触、收势展开，明确支撑与受力；不靠“激烈打斗”替代动作，也不为细化动作增加镜头、路线、时长或无依据连招。
- **背景和状态不串镜。** 保留 `appearance_sources`、`background_constraints`、`state_scope`、`video_usage`；全景设施不自动进入局部背景，参考图状态不提前进入视频。
- **限制进入每条完整生图 prompt。** API 不自动读取外围规则；以具体正面设计为主，针对性限制随后，不只堆负面词。
- **生图重点是真实感与细节。** 让场景与物体具有真实结构、材料差异和可信光照，按景别补细节；不把图片优化转成增加动作姿势图，也不把“真实”统一写成脏旧、潮湿或过度锐化。
- **主动补充合理环境内容。** 开放街道可有远景小比例路人、日常设施和合理背景车辆；树林可有树木疏密、林下植物、落叶、枯枝和地表层次。按地点、时段、季节选择，不一律无人，不改变主要行动路线、关键遮挡或剧情结果。
- **无生成后视觉检查与质量重试。** 仅作 JSON、文件、解码、图号绑定等机械检查，不称为视觉合格，不暗加验图模型或修图循环。
