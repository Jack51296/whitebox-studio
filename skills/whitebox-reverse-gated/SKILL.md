# 带闸门的白模反推

来源：[D2] MCP 反向推理白膜视频（反推 → 静态闸门 → 动画 → 动态穿模闸门 → 渲染 → 验收）与 Omni 线上反推；
[D7] 面部范围高斯模糊。scene.json 是唯一数据源，建场脚本只读 JSON、不硬编码；方向一律用带符号数值。

## 前提（缺一不做）

- 源视频有明确授权，登记在 `--license`（例如“自有拍摄”“已获授权：合同号 …”）。没有授权就停下说明。
- 外发前人脸打码并人工抽检；本 Skill 只导出提交包，不上传。

## 步骤

1. 分析：
   ```
   wbs reverse analyze --batch R20260927 --job R001 --video 源视频.mp4 --license "自有拍摄"
   ```
   输出 `analysis/analysis.json` 与抽帧（13 张均匀 + 首/中/尾各 6 帧 + 每镜首/中/尾）。切镜用“孤立尖峰”判据，
   光流遮蔽主体后 RANSAC 拟合，得到带符号的缩放/位移/滚转。主体框默认由运动残差测量；配置了视觉模型并确认付费后，
   由模型看首/中/尾帧标注（`--annotate`，结果注明来源）。动作事件表需要看图理解，离线分析记为 not_run。
2. 求解与闸门：
   ```
   wbs reverse solve 工作区/batches/R20260927/R001 --subject person --lens 28
   ```
   - 静态闸门用最终相机渲染每镜首/中/尾帧，与原片比较：布局相似度、结构线倾角 ≤15°、镜像（相机摇向与主体横移符号回验）、
     主体占幅差 ≤10%、体块互嵌 >0.3 m 禁止。每个比较都有“原片｜白模｜白模镜像”三图证据（reports/static_gate/）。
   - 不过时按原因修正（修正代理默认 mock）：镜像 → 相机轨迹 X 一次取负；方位 → 整体旋转相机轨迹；占幅 → 沿视线调整机位距离。
     最多两轮，全部记录在 `reports/反推修正记录.json`。
   - 然后动态穿模闸门，再整段渲染和全部自动质检。
3. 在线转换（可选）：`wbs reverse online-package <任务目录> --subject person`。四宫格样板图来自本任务自己的白模渲染（不用原片画面代替）。

## 判断规则

- 草稿求解是单目启发式：摇与移不可区分（按摇处理）、单主体、尺度来自假定的主体身高与相机高度。闸门失败就如实报告失败，
  不调整阈值去凑通过。
- 布局相似度是粗粒度指标，必须有人看三图证据后再用 `wbs review mark` 标记 sampled_visual。
- 不把原片画面、人脸或第三方素材放进任何外发包以外的地方；工作区只在本机。
